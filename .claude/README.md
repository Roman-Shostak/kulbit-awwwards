# Папка `.claude` — конфігурація Claude Code для цього проєкту

Тут лежить усе, що керує поведінкою Claude у проєкті: правила, скіли, агенти, хуки та
налаштування. Інструкції для ШІ написані англійською (так Claude виконує їх точніше),
а цей файл — для людини: що де лежить, навіщо і коли цим користуватися.

> Правило: **додав щось нове в `.claude/` — опиши це тут** (що це, для чого, коли і як
> використовувати). Без запису в цьому файлі зміна вважається незавершеною.

## Як це все читається Claude

| Що | Коли завантажується | Хто викликає |
| --- | --- | --- |
| `CLAUDE.md` (корінь) | завжди, на старті сесії | автоматично |
| `rules/*.md` без `paths` | завжди, на старті сесії | автоматично |
| `rules/*.md` з `paths` | коли Claude відкриває файл, що підходить під шаблон | автоматично |
| `skills/*/SKILL.md` | коли ви пишете `/назва` або Claude сам вирішує, що скіл підходить | ви або Claude |
| `agents/*.md` | коли Claude делегує задачу субагенту | Claude (або ви попросили) |
| `hooks/*` | на подіях, вказаних у `settings.json` | автоматично, це не ШІ, а shell-скрипт |
| `settings.json` | завжди | автоматично |

## `settings.json` — налаштування проєкту (спільні, у git)

Що всередині:

- **`permissions.allow`** — команди, які Claude виконує без підтвердження:
  `pnpm check`, `pnpm build`, `pnpm dev`, `pnpm preview`, `pnpm astro *`, `pnpm install`, `pnpm outdated`,
  `pnpm list`, `pnpm og`, `pnpm fonts`, `pnpm favicon`, `pnpm shot`, `pnpm seo`, скрипт `/systemize` (`node .claude/skills/systemize/scripts/collect.mjs`), а також git-команди,
  потрібні ланцюжку `/figma-page`: `git status`, `git log`, `git diff`, `git add`, `git commit`,
  `git push origin stage`, `git pull --rebase origin stage` (пуш дозволено лише в `stage`; `main`,
  `--force`, `stash`, `reset` дозволу не мають і завжди питають).
  Додавайте сюди лише безпечні команди без побічних ефектів поза проєктом.
- **`permissions.deny`** — заборона читати `.env`, `.env.*` та `.dev.vars*` (секрети Worker-а для
  `pnpm worker`), щоб ключі клієнтів не потрапляли в контекст моделі.
- **`hooks`** — реєстрація хуків (див. нижче): `SessionStart` → `session-start.sh`, `PreToolUse` (Edit/Write/MultiEdit) → `remind-rules.sh`.
- **`attribution`** — `commit: ""` і `pr: ""`: Claude Code не додає в коміти трейлер
  `Co-Authored-By: Claude …`, а в PR — «Generated with Claude Code». Автор комітів лише git-користувач
  проєкту (правило `core.md` §6). Не прибирайте ці порожні рядки: без них атрибуція повертається.

Коли правити: коли Claude занадто часто запитує дозвіл на одну й ту саму безпечну команду,
або коли з'являється новий хук.

`settings.local.json` (не в git, у `.gitignore`) — ваші особисті перекриття цих налаштувань
на цій машині. Створюється за потреби.

## `skills/` — покрокові інструкції для повторюваних задач

## `hooks/` — shell-скрипти на події

Хуки виконує сам Claude Code (не модель), тому вони спрацьовують гарантовано. Реєструються
в `settings.json` → `hooks`.

| Скрипт | Подія | Що робить |
| --- | --- | --- |
| `session-start.sh` | `SessionStart` | На старті сесії перевіряє, чи є `fonttools` + `brotli` для `pnpm fonts`, і тихо ставить їх користувачу (`pip install --user`), якщо бракує; визначає середовище (локальна машина чи хмарний сендбокс, де заблокований `www.figma.com` і Playwright стоїть глобально) і підкидає Claude відповідну підказку з планом Б. Нічого не блокує; таймаут 90 с |
| `remind-rules.sh` | `PreToolUse` для `Edit`, `Write`, `MultiEdit` | Перед кожним створенням чи зміною файлу підкидає Claude нагадування: «рівно те, що названо в поточному запиті, без логічних продовжень». Для `.astro` додає стислий чекліст методології (формат секції, container сам, ≤3 класи без `data-*`/`is--*`, text-size-*, spacing-*, видимість лише на обгортці без scoped `display`, адаптив у тому ж проході, стани, ui-компоненти, `data-*`/`is--*`, зображення з `fill-box`, дані з `site.ts`, іконки-посилання через `sr-only`), для `src/components/ui/` і `src/components/sections/` — нагадування додати компонент/секцію на `/dev/components`, для `src/styles/` — правила токенів (під заголовок групи → `/dev/tokens`), темного режиму й motion-токенів, для `src/data/site.ts` — «лише дані від клієнта», для `src/assets/`/`public/` — правила ассетів, шрифтів і фавікона, для `.claude/` — нагадування оновити цей README. Нічого не блокує; пункт «NO INSTANT CHANGES» для `.astro` Для стилів і `.astro` нагадує про фазу з `src/dev/inventory.md`: `development` — значення точно як у Figma, без нових токенів і плейсхолдерних утиліт; `systemized` — токени першими |

Перевірити хуки вручну:

```bash
echo '{"tool_name":"Edit","tool_input":{"file_path":"src/x.astro"}}' | .claude/hooks/remind-rules.sh
.claude/hooks/session-start.sh
```

**Коли додавати хук:** коли потрібна дія, яка має відбуватися **завжди** без участі моделі
(автоформатування після правки, перевірка типів після відповіді, блокування небезпечних
команд). Доступні події: `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`,
`PostToolUseFailure`, `Stop`, `SessionEnd` та інші.

## Чого тут свідомо немає

- `commands/` — застарілий формат, замінений на `skills/`.
