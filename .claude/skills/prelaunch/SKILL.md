# Pre-launch check

Input: none (the whole site), optionally the production domain. Output: a pass/fail report; fixes
only for what this skill owns (config options, missing generated files); everything else is listed,
not built (rule zero).

The files that must be fresh on every deploy are **generated by the build**, never edited by hand:
`scripts/seo-files.mjs` (registered in `astro.config.mjs` as `seoFiles()`) writes `robots.txt`,
`sitemap.xml`, `llms.txt` and `llms-full.txt` into `dist/` from `site` and the built pages
(`noindex` pages and the 404 page are excluded). `scripts/build-og.mjs` (`prebuild`) writes
`public/og/*.jpg`. So "updating before deploy" = `pnpm build`; this skill verifies the result.

## Steps

1. **Production URL.** `site` in `astro.config.mjs` is the final `https://` domain (no path, no
   trailing slash). Without it canonical, OG, the schema graph and all generated files are wrong or
   missing — stop and ask for the domain if it is still a preview address (`*.workers.dev`, `*.pages.dev`)
   or a placeholder (`example.com` fails `pnpm seo`).
2. **Build and SEO.** `pnpm check` and `pnpm build` (no pipes) pass; `pnpm seo` reports 0 errors.
   Warnings (title/description outside the recommended lengths, missing `og:image`) go to the report.
3. **Generated files** in `dist/`:
   - `robots.txt`: `User-agent: *` / `Allow: /`, an absolute `Sitemap:` line, `Disallow:` only for
     paths the client named (thank-you pages, private areas — `seoFiles({ disallow: [...] })`);
     AI crawlers blocked only if the client asked (`blockAiCrawlers: true`).
   - `sitemap.xml`: every public page once, no `noindex`/dev/404 URLs, `lastmod` present when git
     history exists (`lastmod: 'git' | 'build' | false`).
   - `llms.txt`: the site name (from `og:site_name` = `site.name`), the home description as the
     summary, one line per public page with title and description; `llms-full.txt` with the page
     texts. Read them: nonsense titles or empty descriptions mean the pages' SEO is not done (`/seo`).
4. **Icons and previews.** `public/favicon.svg`, `favicon.ico`, `apple-touch-icon.png` exist
   (`pnpm favicon`); every public page passes `ogImage` and `public/og/<page>.jpg` exists (1200×630).
5. **404 page.** `src/pages/404.astro` exists (with `noindex`, the header/footer, a link home). If
   missing, list it — build it only when the user asks (it needs a design or at least copy).
6. **Client data.** `src/data/site.ts` has `name`, contacts and socials that the client gave; every
   language registered in `src/i18n/index.ts` has a complete dictionary from the client (no default-language
   text in another language's file), the languages in `src/i18n/index.ts` match the language of the page
   texts, the built pages carry reciprocal `hreflang` + `x-default`; no emoji left in `src/` (`grep -rnP
   "[\x{1F1E6}-\x{1F1FF}]" src` is empty — flags are SVG, `images.md`); `grep -rn "TODO\|href=\"#\"" src` is empty or every hit is listed with what the client
   must provide (link targets, form handler, photos, fonts).
7. **Fonts.** If the client delivered fonts: `fonts` in `astro.config.mjs` is filled, `<Font>` is
   in the layout, `src/assets/fonts/*.woff2` exist; no weight/style is used in CSS without a file.
8. **Runtime check.** `pnpm shot --check` (after the build) opens every public page from the
   sitemap at 1540/768/390, saves the screenshots and prints console errors, failed requests and
   4xx/5xx responses per page — all must be empty. Look at the screenshots once.
9. **Security headers** (PageSpeed → Best Practices → "Trust and Safety" lists them as High for
   every visitor of the report). They are response headers, so they live in the host's config, not
   in the template: `X-Frame-Options: SAMEORIGIN` and `Cross-Origin-Opener-Policy: same-origin` for
   `/(.*)` in `vercel.json` `headers` / `netlify.toml` `[[headers]]` / `_headers` — add them for the
   client's host when the host is known. CSP: the ready block `security.csp` in `astro.config.mjs`
   (commented) — enable only with the client's external resources listed (iframes, analytics, form
   handler, CDNs), then `pnpm build && pnpm shot --check` must stay clean (a CSP violation is a
   console error). Report which of the four are set.
   `public/_headers` also ships `X-Robots-Tag: noindex` in the `/*` block (`TODO: remove at launch`) so a new site
   stays out of search until the client approves it: remove that line for the launch, and after the deploy
   `curl -sI https://<domain>/` must return no `x-robots-tag` (stage stays closed by the Worker, not by this file).
10. **Hosting notes** for the report: static `dist/` (no adapter); the platform must serve
   `dist/404.html` for unknown URLs and keep `/sitemap.xml`, `/robots.txt`, `/llms.txt` at the
   root; set the domain in `site` before the final build; HTTPS with a redirect from `http://`
   and from `www`/non-`www` to the canonical host.

## Do not
- Do not build anything the user did not name in this request: the 404 page, missing sections,
  copy or images are reported, not invented.
- Do not edit `dist/` files by hand — change the `seoFiles()` options or the pages and rebuild.
- Do not change `site` to a guess; ask for the domain.
- Do not block AI crawlers, add `noindex` or `Disallow` paths without the client's decision.
