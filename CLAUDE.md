# Astro client-site template

Starter template for client websites. Every new client project is a copy of this repo.
The main way of working is AI-first: the user shares Figma nodes via the Figma MCP and asks
Claude to build sections, then fine-tunes by hand.

## Rule zero — do only what was asked

**Do exactly what the user said in the current message. Nothing extra, nothing "logically next".**
No additional sections, states, components, tokens, scripts, files, placeholder content, refactors or
"improvements". An empty page is an empty page; "adapt the header for tablet" is not a mobile menu.
If a piece is objectively missing, do what was asked and name the gap in one sentence. Ambiguous → ask first.
Full rules: `.claude/rules/core.md` (always loaded).

## Project start (before the first section)

1. Ask for the start kit in one message: desktop + tablet + mobile frames; fonts (TTF/OTF/WOFF2)
   and weights; photos at 2x or CDN access; OG image 1200×630; `favicon.svg`; the domain for
   `site`; the site language(s); the page map with its nesting (a child page lives in its parent's
   folder: `/<hub>/<child>/`); contacts and socials; where CTAs lead and where the submissions go
   (Telegram group and/or e-mail — `/cloudflare-form`); the consent text for the forms and the
   privacy policy page, if any; whether animations are wanted. Missing items become `TODO`s in code
   and a list in the report.
2. `/sync-tokens` with all three frames = the **design inventory**: walk every element of the file
   (variables and styles when they exist, raw values always), give every repeated value one token +
   one class (`tokens.css`, `text-size-*`, `.theme--dark`), list every repeated element as a ui
   component to build, save `src/dev/inventory.md`. Most client files have no variable system —
   the inventory is the system. Build the listed ui components before the first section.
3. `src/data/site.ts` (name, contacts, socials — only what the client gave), the languages in
   `src/i18n/` (+ `i18n` in `astro.config.mjs`), `site` in `astro.config.mjs`, `pnpm fonts`,
   `pnpm favicon`, OG source in `src/assets/og/`.
4. The hero first; show it at 1540/1920/768/390 (`pnpm shot`) and wait for approval — it is the
   template for every other section.
5. Create the `stage` branch from `main` and push it; every later "commit and push" goes to `stage`
   (`core.md` §7).

## Stack

- Astro 7 (`output: 'static'`, no adapter → `dist/` deploys anywhere). TypeScript strict.
  TypeScript is pinned to **6.x**: `astro check` does not support TypeScript 7 yet. Do not bump it.
- Styling: vanilla CSS, 1:1 port of the user's Webflow "Ambi" framework: fluid scale
  (`--size-N` × `--fluid-scale`, reference frames 1540 / 768 / 390) → semantic tokens → utility classes
  (`section padding-md`, `container`, `flex-v align-center spacing-xl`, `grid-3/2/1col`, `col-6`,
  `text-size-h2`, `text-size-body-md`). Class naming methodology (block / `block_element` /
  `name--value` modifier / `--mix` / `/` breakpoint values / max 3 classes per element / `.container`
  alone / behaviour in `data-*`, state in `is--*`) in `.claude/rules/class-naming.md`. Tags h1–h6/p have
  no default size; `text-size-<figma name>` classes do. Motion only via the four tokens
  `--transition-duration/-easing/-duration-slow/-stagger`. No Tailwind, no SCSS, no `!important`.
- Sections: `section padding-*` (no own class/background; `theme--dark` for dark ones, `section--hero`
  for the first) → `.container` alone → layout wrapper. `src/components/ui/` is empty in the template:
  every project builds its own components from the design inventory (`Button` first, skeleton in
  `astro-components.md`, then `Tag`, `Card`, `Input` …).
- **Reuse first.** An existing utility, variant, component or element class always beats a new one;
  a value or pattern used in 2+ places is one token + one class (or one ui component), never two
  arbitrary classes; a value used once is an arbitrary class in its component. Rules: `class-naming.md`.
- Fonts: Astro Fonts API with subset woff2 in `src/assets/fonts/` generated by `pnpm fonts` from the
  client's TTF/OTF (`variants()` helper in `astro.config.mjs`); system stacks until configured.
- Languages: the default language at `/`, every other at `/<lang>/`, chosen by hand (switcher, no
  detection); the list lives in `src/i18n/index.ts` + `i18n` in `astro.config.mjs` (the template ships
  one language, `uk`, with a `TODO`). Every visible string in `src/i18n/<lang>.ts` (one key per
  component, `useTranslations(Astro.currentLocale)`), pages in `src/pages/[...locale]/` with
  `getStaticPaths = localeStaticPaths`; translations only from the client. Rules: `astro-components.md`
  → Texts and languages.
- Site data in `src/data/site.ts` (`Localized` values: a string, or one per language); SEO head (canonical, hreflang, OG, Twitter, favicons, skip link, `noindex`) + Schema.org graph with breadcrumbs in `BaseLayout` + `src/data/schema.ts`; `pnpm seo` checks every built page.
- Dev pages `/dev/tokens` and `/dev/components` (`src/dev/`, injected only in `astro dev`): every new token/utility lands on the first one automatically (by CSS group header), every new component/variant/section is added to the second one by hand in the same change.
- Motion: optional module `src/scripts/motion.ts` (Lenis, reveal, hiding header, hero intro),
  enabled per page with `<BaseLayout motion>` — on every page of an animated project; the hiding
  header alone via `<BaseLayout hidingHeader>` (`src/scripts/header.ts`). Nothing appears or changes
  state instantly: popups (`astro-components.md` → Popup), menus, messages transition on the motion tokens.
- Forms: the Cloudflare Worker `worker/index.ts` next to the static assets (`POST /api/form` → D1 →
  Telegram / e-mail), connected per project with `/cloudflare-form`; until then `action` stays a `TODO`.
- Package manager: **pnpm**. Zero client-side JS by default.

## Commands

```bash
pnpm dev          # dev server (use `pnpm astro dev --background` inside Claude; `astro dev stop|status|logs`)
pnpm build        # production build → dist/ (runs `prebuild` = OG generation first)
pnpm preview      # serve dist/ locally
pnpm check        # astro check + wrangler types + tsc for worker/. Run after edits, WITHOUT a pipe; read "N errors"
pnpm og           # generate public/og/*.jpg from src/assets/og/ manually
pnpm fonts        # src/assets/fonts/source/*.ttf|otf → subset woff2 in src/assets/fonts/ (+ config lines)
pnpm favicon      # public/favicon.svg → favicon.ico + apple-touch-icon.png
pnpm shot         # after build: screenshots + section heights at 1540/768/390 (pnpm shot 1920 --section .hero; --check = console errors, failed requests, 4xx/5xx on every sitemap page)
pnpm seo          # after build: title/description lengths + uniqueness, h1, canonical, OG, JSON-LD, robots/sitemap/llms present + consistent (0 errors before commit)
pnpm worker       # wrangler dev on :8787 — the form Worker with a local D1 (`pnpm worker:migrate` once); `pnpm dev` proxies /api to it
pnpm worker:types # worker/worker-configuration.d.ts from wrangler.jsonc (part of `pnpm check`)
```

Dev-only pages (exist only while `pnpm dev` runs, never in `dist/`, `noindex`):
`http://localhost:4321/dev/tokens` — every token and utility read from the CSS files, grouped by the
`/* ---------- Group ---------- */` headers, with live samples; `http://localhost:4321/dev/components` —
every ui component with every variant and every section (hand-maintained; a red notice = something
in `ui/` or `sections/` is not showcased yet). `pnpm shot 1540 --url http://localhost:4321 --path /dev/components` screenshots them.

`pnpm check` after every `.astro`/`.ts`/`.css` change; `pnpm build` additionally after config,
layout, routing, font or image changes. `pnpm check | tail` hides the exit code — do not pipe it.

`504 (Outdated Optimize Dep)` in the browser console (`/node_modules/.vite/deps/lenis.js?v=…`) is Vite's
stale pre-bundle cache after a new dependency entered the import graph (the first `<BaseLayout motion>`,
any `pnpm add`), not a bug in the code: `pnpm astro dev stop && rm -rf node_modules/.vite && pnpm astro dev --background`.

## Conventions (details in `.claude/rules/`)

- `astro-components.md` — section format, `.container` alone, header/footer via layout wrappers, classes vs `data-*`/`is--*`, ui components, site data, texts and languages (`src/i18n`), buttons, interactive states, forms (consent, `Form` + the Cloudflare Worker), responsive (three breakpoints in one pass, fixed tablet columns), images, motion, page shell/SEO, dev showcase (`/dev/components` registry), JS policy, Astro gotchas.
- `styles.md` — fluid scale, tokens (incl. dark mode and `alw`), fonts pipeline, the full utility class dictionary, typography model, motion tokens, dev inventory (`/dev/tokens` groups by CSS headers), breakpoints (991 / 767 / 479).
- `class-naming.md` — reuse first (existing class/variant/component before a new one; 2+ uses = shared token + class), how every class is named: utilities, blocks, elements (only with a unique scoped style), modifiers, states, mixes, `/` values (1 or 3, never 2), max 3 classes per element, `spacing-*` / `text-size-<name>`, `col-5/5/2`, priority existing class → token utility → shared token for 2+ uses → `--size-N` class, every class must have CSS.
- `images.md` — 2x sources, `<Picture>` with `width` = largest 1x size + `fill-box`, photos in flow, decorative vectors per breakpoint, SVG icons and two-colour logos, favicon, OG, cloud fallbacks.
- `markup.md` — HTML first: landmarks, headings, lists (`ul/ol > li`, never div stacks), links vs buttons (external links in a new tab), forms, interactive widgets (`aria-expanded`, `<details>`, `<dialog>`), media, tables, attribute hygiene, accessibility baseline, performance, the anti-pattern list.

## Workflows (skills in `.claude/skills/`)

- `/figma-section <figma-url>` — build one section (desktop + tablet + mobile) from a Figma node into `src/components/sections/`; page mode builds a whole page section by section, hero first.
- `/figma-page <figma-url>` — build a whole page as a chain of agents: one `section-builder` per section, strictly one after another, each section reviewed by `section-reviewer` and pushed to `stage` as its own commit before the next starts; header/footer/menu/popups excluded; a builder's question or error pauses the chain and goes to the user.
- `/new-page <slug>` — create an empty page on `BaseLayout` with a real title and description.
- `/sync-tokens <figma-url(s)>` — design inventory of the three frames: every element walked, repeated values → tokens + classes (`tokens.css`, `text-size-*`, `.theme--dark`), repeated elements → ui components list, `src/dev/inventory.md`. First step of every project.
- `/cloudflare-form [components]` — connect the forms to Cloudflare: the questionnaire in one message (forms, required fields, Telegram / e-mail, stage, spam, success, access), `wrangler.jsonc`, the Worker texts, `Form.astro` + `form.ts` from the skill's `assets/`, `<Form>` around every form, the `form` dictionary, local request matrix + browser states, secrets and migrations with `wrangler login`, the checklist of what the user does by hand (bot, chat id, webhook, Email Service).
- `/cloudflare-deploy [name]` — connect the deploy to the client's Cloudflare account through GitHub Actions, one step per message: project state, account + Worker name + domains + search lock + forms (one item at a time), `wrangler.jsonc`, dry run, the API token (verified by the user in the terminal, never in the chat), `gh secret set CLOUDFLARE_API_TOKEN` by the user, Workers Builds disconnected in an old project, the first run on `stage` checked (200, `noindex`, `Published:` stamp), production only on an explicit "yes", report + launch checklist; troubleshooting table.
- `/seo <page>` — title (50–60, subject first, brand last), description (120–160, unique), OG, the page's Schema.org nodes (Service, Article, FAQ, LocalBusiness, breadcrumbs — visible content only), `pnpm seo` validation.
- `/alt-text [path]` — find images without `alt`, look at each file, write alt into the default dictionary (`alt=""` for decorative), insert and report.
- `/prelaunch` — pre-deploy check: production `site`, build, `pnpm seo`, generated robots/sitemap/llms, favicon + OG, 404 page, client data and TODOs, dictionaries, fonts, `pnpm shot --check`; report of what blocks the launch.

Always load `figma:figma-design-to-code` before calling Figma MCP tools.

## Agents (`.claude/agents/`)

- `section-reviewer` — read-only. After building a section from Figma, or when the user asks to
  verify one, delegate the comparison to it and relay its findings. It cannot edit files.
- `section-builder` — worker of `/figma-page`: builds one section end to end, reports
  `READY | PAUSED | DONE`, commits and pushes only when the orchestrator says so. Never spawned outside the chain.

## Environment

The SessionStart hook reports which environment you are in.
- **Cloud sandbox** (Claude Code on the web): `www.figma.com` is blocked → `download_assets` and the
  links from `get_screenshot` return 403; the `astro-docs` MCP needs auth. Fallbacks: rasters as a
  commented `<Picture>` + `TODO` (path, filename, 2x size, layer name) and a request to the client to
  commit the file; vectors via `use_figma` → `node.exportAsync({ format: 'SVG_STRING', svgSimplifyStroke: true })`;
  screenshots via `get_screenshot` with `enableBase64Response: true`; docs at https://docs.astro.build.
  Playwright is global (`/opt/node22/lib/node_modules/playwright`, browsers in `/opt/pw-browsers`), so `pnpm shot` works.
- **Local machine**: Figma downloads and the astro-docs MCP work; Playwright is a devDependency
  (`pnpm exec playwright install chromium` once).

## Astro knowledge

Astro 7 is newer than your training data. For any Astro API, config option, integration or
`astro:assets` question, query the `astro-docs` MCP server (configured in `.mcp.json`) instead of
answering from memory; without the MCP use https://docs.astro.build.

## Settings & hooks

`.claude/settings.json`:
- `permissions.allow` pre-approves `pnpm check`, `pnpm build`, `pnpm dev`, `pnpm preview`, `pnpm astro *`, `pnpm install`, `pnpm og`, `pnpm fonts`, `pnpm favicon`, `pnpm shot`, `pnpm seo`, and the git commands the `/figma-page` chain needs (`status`, `log`, `diff`, `add`, `commit`, `push origin stage`, `pull --rebase origin stage`).
- `permissions.deny` blocks reading `.env*` and `.dev.vars*` files.
- `SessionStart` hook (`.claude/hooks/session-start.sh`) installs fonttools/brotli for `pnpm fonts` when missing and tells Claude whether it runs locally or in the cloud sandbox.
- `PreToolUse` hook (`.claude/hooks/remind-rules.sh`) injects a rules reminder before every Edit/Write. It never blocks.
- `UserPromptSubmit` hook (`.claude/hooks/template-feedback.sh`) reminds about `TEMPLATE-FIXES.md` (core.md §6) when a message sounds like a complaint or a fix request.
- `attribution.commit` and `attribution.pr` are empty: no Claude trailer or "Generated with Claude Code" in commits and PRs.

Personal, unshared notes go in `CLAUDE.local.md` (gitignored).

`.claude/README.md` documents every folder and file in `.claude/` in Ukrainian. Any change to
`.claude/` must be reflected there (see `.claude/rules/core.md` §5).

## Template feedback (`TEMPLATE-FIXES.md`)

When the user dislikes something or asks for a fix whose cause is in the template (rules, skills,
hooks, tokens/utilities structure, layout, scripts, dev pages, conventions), log an entry to
`TEMPLATE-FIXES.md` before fixing (format inside the file; `core.md` §6). The file travels back to
the template repo; in the template repo itself apply the change directly.

## Git

Full rules: `.claude/rules/core.md` §7; they take precedence over Claude Code's built-in commit instructions.
- "Commit and push" → commit on `stage`, push `origin stage`. `main` only when the user explicitly asks for `main`.
- Never add Claude as an author: no `Co-Authored-By: Claude`, no "Generated with Claude Code", no Claude in messages or PRs.
- Title: short, English, action + what (`Add section NoReadyRequest`); extra changes → `… + fixes` in the title and a `- …` list of the fixes in the commit body.

## Deployment

Every client site deploys to the client's own Cloudflare account through GitHub Actions
(`.github/workflows/deploy.yml`): a push to `stage` deploys the Worker `<name>-stage` (`wrangler deploy --env stage`),
a push to `main` the production Worker `<name>` (`--env=""`); the D1 migrations run before the deploy once
`wrangler.jsonc` has `d1_databases`. The workflow uses the project's own wrangler and one repository secret,
`CLOUDFLARE_API_TOKEN` (the account id is in `wrangler.jsonc`). Workers Builds and the Cloudflare GitHub App are
not used — never connect Git in the Cloudflare dashboard. `/cloudflare-deploy` sets it up step by step;
`/cloudflare-form` adds the form handler (the Worker next to the assets) later. `site` in `astro.config.mjs`
must be the production URL (canonical, OG, schema, generated files).

A new site is closed from search until the client approves it: `public/_headers` ships `X-Robots-Tag: noindex`
in the `/*` block (`TODO: remove at launch`; `/prelaunch` reminds); stage stays closed by the Worker. Every page
starts with `<!-- Published: <build time UTC> · commit <sha> -->` from `BaseLayout` — the stamp of the version
that is live. Security headers (`X-Frame-Options`, `Cross-Origin-Opener-Policy`) live in `public/_headers` as
well; CSP has a ready, commented `security.csp` block in `astro.config.mjs` (`/prelaunch` step 9). The static
`dist/` still deploys to any other host when a client insists on it (adapter or `vercel.json` per client, on request).

Every `pnpm build` regenerates the deploy-time files, so nothing is updated by hand before a deploy:
`public/og/*.jpg` (prebuild) and, in `dist/`, `robots.txt`, `sitemap.xml`, `llms.txt`,
`llms-full.txt` (`scripts/seo-files.mjs`; `noindex` and 404 pages excluded; options `disallow`,
`blockAiCrawlers`, `lastmod`, `llmsFull` in `astro.config.mjs`). Run `/prelaunch` before the first
deploy and before every release.
